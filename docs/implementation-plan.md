# Savebeam 实施计划

> 状态：Draft 1.0
> 更新日期：2026-10-20
> 技术依据：[软件设计说明书](software-design.md)

## 1. 文档目的

本文档只管理 Savebeam 的执行顺序、任务状态、提交规范和里程碑验收。技术方案、架构和交互设计以《软件设计说明书》为准；技术方案发生变化时，先更新设计说明书，再调整本计划。

## 2. 执行规则

- 上一里程碑验收通过后再进入下一里程碑。
- 每个任务对应独立、可审查的改动。
- 每个任务实现并验证完成后提交一笔；一个任务不得和下一个任务混在同一提交中。
- 任务提交包含该任务所需的代码、测试及文档/清单状态更新。
- 同一任务修复自身验证失败可以继续纳入该任务提交；提交后发现的新问题应新增修复任务并另行提交。
- 一个里程碑的全部任务提交完成后，执行该里程碑的完整验收。
- 里程碑验收通过后再提交一笔“里程碑验证提交”，包含验收记录、最终清单状态和必要的文档更新，不创建空提交。
- 里程碑验证失败时不得提交里程碑完成提交；先完成修复任务及其独立提交，再重新验收。
- `pnpm build` 和相关 Rust 测试是每个里程碑的最低回归检查。
- 日常开发和任务级验证在 macOS Apple Silicon 上进行；Windows/Linux 专项验证必须如实记录，未经验证不得推断通过。

建议提交信息格式：

```text
feat(m0-t1): update application metadata
test(m3-t6): cover media inspection process integration
fix(m4-t6): terminate child process tree on cancellation
chore(milestone): verify M4 single-download workflow
```

里程碑验收记录保存到 `docs/verification/MX.md`，至少包括：

- 验收日期和执行平台。
- 对应任务提交列表。
- 执行的命令和结果。
- 手动验证项目和结果。
- 已知限制及延后事项。
- 是否满足进入下一里程碑的条件。

## 3. 里程碑

### M0：工程基线与开发规范

**目标**：把模板整理成可持续开发的工程。

任务：

- [x] M0-T0 初始化 Git 仓库，确认忽略规则并建立任务提交基线。
- [x] M0-T1 更新应用名称、描述、作者和窗口基础配置。
- [x] M0-T2 确认 bundle identifier、版本策略和最低系统版本。
- [x] M0-T3 整理目录结构，建立 `commands/domain/services/infrastructure/security` 模块。
- [x] M0-T4 配置 Rust 格式化、Clippy、前端 lint/format 和以 macOS 为首要环境的基础 CI。
- [x] M0-T5 建立错误类型、IPC 响应约定和事件命名规范。
- [x] M0-T6 更新 README，记录 pnpm、RustRover 和运行命令。
- [x] M0-T7 清理预验收发现的模板欢迎页、失效 `greet` 调用和无关模板资源。

验收标准：

- `pnpm tauri dev` 正常启动。
- 前端生产构建和 Rust 检查通过。
- CI 能在至少一个桌面平台运行基础检查。
- 模板欢迎页面和无关资源被清理。

验收状态：已通过，证据见 [`docs/verification/M0.md`](verification/M0.md)。

### M1：平台自适应应用外壳与交互原型

**目标**：完成真实页面结构，但暂不执行下载。

任务：

- [x] M1-T1 集成 Mantine、Tabler Icons、Zustand 和 React Router，建立基础 design tokens 与平台 profile。
- [x] M1-T2 实现共享 AppShell、左侧导航、右侧内容区、页面工具栏和状态栏。
- [x] M1-T3 实现 URL 输入与客户端基础校验。
- [x] M1-T4 实现组件缺失、空状态、加载状态和错误状态组件。
- [ ] M1-T5 建立前端领域类型和 IPC client 封装。
- [ ] M1-T6 完成键盘导航、焦点状态、平台快捷键和基础无障碍检查。
- [ ] M1-T7 实现 macOS、Windows、Linux profile 的开发环境强制切换与视觉检查。

验收标准：

- 四个主要页面可导航。
- 默认窗口和最小支持窗口下布局可用，紧凑导航不会丢失可访问名称。
- macOS profile 接近 SwiftUI `NavigationSplitView`，Windows profile 接近 WinUI 3 `NavigationView`，但不复制业务页面。
- 系统原生标题栏和窗口装饰保持可用。
- UI 不直接依赖 shell 插件。
- 使用模拟数据可走完“输入 URL → 选择格式 → 创建假任务”流程。

### M2：组件检测与设置页

**目标**：可靠发现和验证 yt-dlp、FFmpeg、ffprobe，以及 Deno/Node.js/Bun/QuickJS 中可用的 JavaScript runtime。

任务：

- [ ] M2-T1 定义 `ComponentKind/Source/Status/Installation` 领域模型。
- [ ] M2-T2 实现应用管理目录和跨平台路径策略。
- [ ] M2-T3 实现自定义路径、应用目录、常见系统路径和 PATH 检测。
- [ ] M2-T4 实现各组件版本命令和最低能力检查。
- [ ] M2-T5 实现“运行组件”设置页面。
- [ ] M2-T6 实现包管理器说明、复制命令和重新检测。
- [ ] M2-T7 为检测优先级和版本解析编写测试。

验收标准：

- 能区分 `AppManaged/System/Custom`。
- 能显示组件实际路径、版本和健康状态。
- 不会覆盖系统或自定义组件。
- 从 Finder 启动的 macOS 应用仍能发现常见 Homebrew 路径。

### M3：媒体信息解析

**目标**：输入 URL 后获得稳定、可展示的媒体信息。

任务：

- [ ] M3-T1 实现 `YtDlpProcessEngine.inspect`。
- [ ] M3-T2 定义 `MediaInfo/FormatOption/SubtitleTrack`。
- [ ] M3-T3 将 yt-dlp JSON 映射为内部稳定模型。
- [ ] M3-T4 实现超时、取消和错误分类。
- [ ] M3-T5 实现媒体卡片、封面、格式和字幕选择。
- [ ] M3-T6 使用假可执行程序完成集成测试。

验收标准：

- 普通单视频 URL 可以展示标题、封面和可用格式。
- 不支持、需要登录和网络失败有不同提示。
- 前端不依赖 yt-dlp 原始 JSON 字段细节。
- 输入内容不能注入额外命令参数。

### M4：单任务下载闭环

**目标**：可靠完成一个视频的本地下载。

任务：

- [ ] M4-T1 定义 `DownloadOptions/Task/Progress/Result`。
- [ ] M4-T2 实现安全的 yt-dlp 参数构造器。
- [ ] M4-T3 实现 `ProcessSupervisor` 和结构化进度读取。
- [ ] M4-T4 实现任务状态机和 Tauri 事件。
- [ ] M4-T5 实现下载进度、速度、剩余时间和后处理状态 UI。
- [ ] M4-T6 实现取消、失败重试和应用退出处理。
- [ ] M4-T7 验证 FFmpeg 合并和最终文件存在性。

验收标准：

- 可完成单个公开视频下载及音视频合并。
- 取消后无遗留 yt-dlp/FFmpeg 进程。
- 文件名包含空格和非 ASCII 字符时工作正常。
- 日志不暴露敏感 header 或签名 URL。

### M5：任务队列、设置与历史

**目标**：从单次工具升级为可持续使用的桌面应用。

任务：

- [ ] M5-T1 在 Rust 层引入 SQLite 和 migration 机制。
- [ ] M5-T2 实现设置、任务和历史 Repository。
- [ ] M5-T3 实现顺序队列和可配置的有限并发。
- [ ] M5-T4 实现重启后的未完成任务恢复策略。
- [ ] M5-T5 实现历史搜索、打开文件和打开目录。
- [ ] M5-T6 实现默认下载目录、冲突策略和并发设置。
- [ ] M5-T7 实现数据库 migration 和 Repository 测试。

验收标准：

- 重启应用后设置和历史保持。
- 同时任务数不超过用户设置和安全上限。
- 删除历史不删除已下载文件，除非未来提供独立且明确的删除操作。
- 数据库损坏时应用能给出可恢复错误而不是直接崩溃。

### M6：应用管理组件安装与更新

**目标**：用户无需预装命令行工具即可完成本地组件配置。

任务：

- [ ] M6-T1 定义版本化、签名的组件清单格式。
- [ ] M6-T2 实现平台和 CPU 架构匹配。
- [ ] M6-T3 实现带进度的安全下载和取消。
- [ ] M6-T4 实现哈希/签名验证及安全解压。
- [ ] M6-T5 实现安装、健康检查、原子切换和回滚。
- [ ] M6-T6 实现组件更新、删除和许可证详情 UI。
- [ ] M6-T7 建立 yt-dlp、FFmpeg、ffprobe 与受支持 JavaScript runtime 的兼容组合测试，至少覆盖应用管理的 Deno。

验收标准：

- 全新系统可通过应用引导安装组件。
- 校验失败的文件绝不进入可执行目录。
- 更新失败自动继续使用上一版本。
- 设置页准确显示实际构建提供者和许可证。

### M7：功能完善与安全加固

**目标**：补齐首个公开测试版本所需能力。

任务：

- [ ] M7-T1 支持播放列表并提供数量确认和安全上限。
- [ ] M7-T2 支持仅音频、字幕、缩略图和元数据选项。
- [ ] M7-T3 支持用户显式选择 `cookies.txt`。
- [ ] M7-T4 完成日志脱敏和用户主动导出诊断包。
- [ ] M7-T5 启用并收紧 CSP 与 Tauri capabilities。
- [ ] M7-T6 完成可访问性、国际化准备和关键错误文案。
- [ ] M7-T7 开展依赖、许可证和组件来源审计。

验收标准：

- 不存在前端通用 shell 执行权限。
- Cookie 不进入数据库和普通日志。
- 播放列表不会在未确认时创建超大任务集合。
- 安全与许可证检查项有记录并关闭高优先级问题。

### M8：桌面发布准备

**目标**：产出可供外部测试的 Windows/macOS 版本。

任务：

- [ ] M8-T1 完成应用图标、安装包名称和版本信息。
- [ ] M8-T2 建立 Windows x64 签名与安装包流水线。
- [ ] M8-T3 建立 macOS Apple Silicon 签名、公证与 DMG 流水线。
- [ ] M8-T4 实现主应用更新机制；组件更新保持独立。
- [ ] M8-T5 完成隐私政策、使用条款和开源许可证页面。
- [ ] M8-T6 执行全新环境、升级、卸载和回滚测试。
- [ ] M8-T7 建立崩溃/问题反馈流程，不默认上传敏感信息。

验收标准：

- Windows 和 macOS 安装包可在全新测试机安装、启动和卸载。
- 签名、公证和版本信息验证通过。
- 无组件环境可清晰引导，不会在后台静默下载。
- 用户能够查看并删除应用管理的所有组件。

## 4. 里程碑依赖关系

```text
M0 工程基线
 └─ M1 应用外壳
     └─ M2 组件检测
         └─ M3 媒体解析
             └─ M4 单任务下载
                 └─ M5 队列与持久化
                     └─ M6 组件安装更新
                         └─ M7 完善与加固
                             └─ M8 发布准备
```

M6 放在下载闭环之后，是为了先通过用户已有组件验证核心业务，再承担跨平台组件分发和更新的复杂度。

## 5. 首个开发切片

开始实现时只执行 M0。推荐顺序：

1. M0-T0：初始化 Git 仓库和提交基线。
2. M0-T1：完善元数据和窗口配置。
3. M0-T3：建立 Rust 模块边界。
4. M0-T5：确定 IPC 和错误约定。
5. M0-T4：建立格式化、检查与 CI。
6. M0-T6：更新 README。
7. M0-T2：在准备首个平台构建前确认最低系统版本和版本策略。

完成 M0 后进行一次架构复核，再进入 M1；不要在 M0 同时接入 yt-dlp 或 FFmpeg。

## 6. 完成定义

单个任务只有同时满足以下条件才可标记完成：

- 实现符合《软件设计说明书》定义的边界。
- 有与风险相称的自动测试或明确的手动验证记录。
- 前端构建和 Rust 检查通过。
- 没有引入未说明的外部网络请求、权限或持久化数据。
- 用户可见行为和错误有清晰文案。
- 相关设计变化已经同步回《软件设计说明书》。
- 已形成一笔只包含该任务范围的 Git 提交。

单个里程碑只有同时满足以下条件才可标记完成：

- 该里程碑的全部任务均满足任务完成定义。
- 在 macOS 日常开发环境完成完整验收；需要的平台专项验证已经执行或被明确列为发布前限制。
- `docs/verification/MX.md` 已记录验收证据和已知限制。
- 已形成一笔里程碑验证提交，且该提交不包含下一里程碑的实现。
