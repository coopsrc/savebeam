# Savebeam 实施计划

> 状态：Draft 1.0
> 更新日期：2026-10-23
> 技术依据：[软件设计说明书](software-design.md)

## 1. 文档目的

本文档只管理 Savebeam 的执行顺序、任务状态、提交规范和里程碑验收。技术方案、架构和交互设计以《软件设计说明书》为准；技术方案发生变化时，先更新设计说明书，再调整本计划。

## 2. 执行规则

- 上一里程碑验收通过后再进入下一里程碑。
- 每个任务对应独立、可审查的改动。
- 每个任务实现并验证完成后提交一笔；一个任务不得和下一个任务混在同一提交中。
- 任务提交包含该任务所需的代码、测试及文档/清单状态更新。
- 同一任务修复自身验证失败可以继续纳入该任务提交；提交后发现的新问题应新增修复任务并另行提交。
- 一个里程碑的全部任务提交完成后，执行该里程碑的完整验收。
- 里程碑验收通过后再提交一笔“里程碑验证提交”，包含验收记录、最终清单状态和必要的文档更新，不创建空提交。
- 里程碑验证失败时不得提交里程碑完成提交；先完成修复任务及其独立提交，再重新验收。
- `pnpm build` 和相关 Rust 测试是每个里程碑的最低回归检查。
- 日常开发和任务级验证在 macOS Apple Silicon 上进行；Windows/Linux 专项验证必须如实记录，未经验证不得推断通过。

建议提交信息格式：

```text
feat(m0-t1): update application metadata
test(m3-t6): cover media inspection process integration
fix(m4-t6): terminate child process tree on cancellation
chore(milestone): verify M4 single-download workflow
```

里程碑验收记录保存到 `docs/verification/MX.md`，至少包括：

- 验收日期和执行平台。
- 对应任务提交列表。
- 执行的命令和结果。
- 手动验证项目和结果。
- 已知限制及延后事项。
- 是否满足进入下一里程碑的条件。

开始实现时只执行 M0。推荐顺序：

1. M0-T0：初始化 Git 仓库和提交基线。
2. M0-T1：完善元数据和窗口配置。
3. M0-T3：建立 Rust 模块边界。
4. M0-T5：确定 IPC 和错误约定。
5. M0-T4：建立格式化、检查与 CI。
6. M0-T6：更新 README。
7. M0-T2：在准备首个平台构建前确认最低系统版本和版本策略。

完成 M0 后进行一次架构复核，再进入 M1；不要在 M0 同时接入 yt-dlp 或 FFmpeg。

## 6. 完成定义

单个任务只有同时满足以下条件才可标记完成：

- 实现符合《软件设计说明书》定义的边界。
- 有与风险相称的自动测试或明确的手动验证记录。
- 前端构建和 Rust 检查通过。
- 没有引入未说明的外部网络请求、权限或持久化数据。
- 用户可见行为和错误有清晰文案。
- 相关设计变化已经同步回《软件设计说明书》。
- 已形成一笔只包含该任务范围的 Git 提交。

单个里程碑只有同时满足以下条件才可标记完成：

- 该里程碑的全部任务均满足任务完成定义。
- 在 macOS 日常开发环境完成完整验收；需要的平台专项验证已经执行或被明确列为发布前限制。
- `docs/verification/MX.md` 已记录验收证据和已知限制。
- 已形成一笔里程碑验证提交，且该提交不包含下一里程碑的实现。
