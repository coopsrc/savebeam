## 1. 文档目的

本文档是 Savebeam 产品边界、技术选型、软件架构、交互设计、安全和数据策略的统一依据。任务、里程碑、提交规则和验收状态由《实施计划》单独管理；技术方案发生变化时，应先更新本文档，再调整实施计划和实现。

## 2. 产品定义

Savebeam 是一个本地优先的桌面媒体下载器。用户粘贴受支持的媒体链接，查看媒体信息和可用格式，选择下载选项，并在本机完成下载、合并和后处理。

### 2.1 核心价值

- 本地运行，不建设云端下载服务。
- URL、Cookie、下载历史和文件保留在用户设备上。
- 提供比命令行更易用的任务队列、进度、错误提示和组件管理体验。
- 下载引擎与 GUI 解耦，便于独立更新和故障隔离。

### 2.2 首发平台

- macOS，Apple Silicon 优先。
- Windows 10/11，x64 优先。
- Linux 作为后续桌面目标，优先支持 Ubuntu/Debian。

日常开发、调试和任务级验证统一在 macOS 上进行。Windows 和 Linux 的平台验证通过 CI、里程碑验收和发布前真实设备测试补充，不要求每个日常任务都在三个平台重复执行。

### 2.3 明确不在首版范围内

- Android 和 iOS 本地下载版本。
- 云端解析、云端代下载、账号系统和跨设备同步。
- DRM 破解、密钥提取、付费墙绕过。
- 文件分享、内容发布和内置媒体交易。
- 浏览器扩展和浏览器 Cookie 自动读取。
- 插件市场及第三方脚本执行。

## 3. 设计原则

1. **本地优先**：用户数据默认不离开设备。
2. **最小权限**：React 前端不能直接执行任意命令或访问任意文件。
3. **组件解耦**：yt-dlp、FFmpeg、ffprobe 和可用的 JavaScript runtime 作为独立外部程序运行。
4. **结构化通信**：优先使用 JSON、固定进度模板和稳定字段，不解析面向人的普通日志。
5. **来源可追溯**：记录组件版本、路径、来源、校验值和安装方式。
6. **失败可恢复**：任务可取消、失败可重试、组件更新可回滚。
7. **合规可见**：组件提供者、许可证和源代码地址在应用内可查看。
8. **先桌面后扩展**：不为了尚未确定的移动端牺牲桌面实现质量。

| -------------- | ----------------------------------------------------- |

| 前端           | React 19、TypeScript、Vite                            |
| UI 组件        | Mantine、Tabler Icons                                 |
| 前端状态与导航 | Zustand、React Router `HashRouter`                    |
| 包管理器       | pnpm                                                  |
| 本地核心       | Rust 2024 Edition                                     |
| IDE            | RustRover                                             |
| 应用标识       | `com.coopsrc.matrix.savebeam`                         |
| 下载引擎       | yt-dlp，后续按需安装                                  |

新依赖必须有明确用途，不应仅因模板或未来可能需要而提前加入。

### 4.1 日常开发环境

- 主开发平台：macOS。
- 主开发架构：Apple Silicon。
- IDE：RustRover。
- Node 环境：nvm 管理，项目使用 pnpm。
- 本地开发命令：`pnpm tauri dev`。
- 任务级验证默认在 macOS 执行，并在任务提交中记录实际运行的检查。
- 涉及平台条件编译、路径、进程管理、安装包或系统集成的任务，不能仅根据 macOS 结果宣称 Windows/Linux 已验证。
- Windows/Linux 验证失败应独立记录和修复，不应在未经验证时推断跨平台行为一致。

### 4.2 平台支持基线

首个桌面版本采用以下最低支持基线：

- macOS 12.0 或更高版本，首发构建为 Apple Silicon。`bundle.macOS.minimumSystemVersion` 必须显式保持为 `12.0`，不能依赖 Tauri 默认值。
- Windows 10 1809（build 17763）或更高版本，首发构建为 x86_64。安装程序负责检测或安装 WebView2 Runtime。
- Linux 以 Ubuntu 22.04 LTS x86_64 或具有 WebKitGTK 4.1 的等价发行版作为兼容基线；Linux 正式安装包是否进入首发范围在 M8 前复核。

最低版本是产品支持边界，不代表仅凭编译成功即可宣称兼容。涉及路径、子进程、系统 WebView、安装器或签名的行为必须在对应平台完成验证。

### 4.3 标识与版本策略

- 正式 bundle identifier 为 `com.coopsrc.matrix.savebeam`，发布后不得因品牌文案或版本变化随意修改，否则系统会把应用视为不同产品。
- 应用版本遵循 SemVer `MAJOR.MINOR.PATCH`；1.0 前使用 `0.MINOR.PATCH`，不兼容的持久化或公开协议变化必须在发布说明中明确。
- `package.json` 的 `version` 是 Tauri 打包版本来源；`tauri.conf.json` 通过路径引用该文件，避免前端包与安装包版本分叉。
- `Cargo.toml` 的 crate 版本在发布任务中与应用版本同步；发布标签使用 `vMAJOR.MINOR.PATCH`。
- yt-dlp、FFmpeg、ffprobe 和 JavaScript runtime 保持各自版本，不跟随应用版本号；组件兼容矩阵独立维护。
- 数据库 schema version、IPC event schema version 和应用 SemVer 相互独立，升级时分别迁移和验证。

### 5.1 信任边界

- React UI 只提交强类型请求，不接收或拼接任意 shell 命令。
- Rust 验证 URL、文件路径、格式 ID、任务 ID 和组件路径。
- 外部程序使用参数数组启动，禁止通过 `sh -c`、`cmd /c` 或字符串拼接执行。
- Tauri capability 仅开放实际需要的命令；不得向前端开放通用 shell execute 权限。
- 原始 stderr 只能进入脱敏诊断日志，不直接作为 HTML 渲染。

## 6. 前端设计

### 6.1 页面结构

```text
App
├─ 下载
│  ├─ URL 输入
│  ├─ 媒体信息预览
│  ├─ 视频画质与音轨
│  └─ 高级设置弹窗 / 开始下载
├─ 任务
│  ├─ 进行中
│  └─ 已完成/失败
├─ 历史
├─ 订阅
│  ├─ 从已下载系列添加 / 填写系列链接
│  ├─ 手动检查新增条目
│  └─ 勾选新增 / 漏下的条目下载
└─ 设置
   ├─ 下载（目录、并发、重名策略、下载选项默认值）
   ├─ 网络与代理（连接方式、代理地址、测试连接）
   ├─ Cookie 与登录（来源、浏览器、敏感权限确认）
   ├─ 运行组件（检测、安装/更新、自定义路径、安装说明及许可提示）
   └─ 隐私与诊断（本地诊断导出）
```

首版采用单窗口响应式布局，以 Mantine 提供基础控件、表单、弹窗和通知，以 Tabler Icons 提供图标。Savebeam 不直接使用 SwiftUI 或 WinUI 3，而是在共享 React 页面上遵循对应平台的信息架构和交互习惯。

### 6.2 UI 技术边界

- Mantine 是唯一基础组件库，不同时引入另一套完整设计系统。
- React Router 使用 `HashRouter`，避免桌面资源协议下的历史路由问题。
- Zustand 只管理任务、组件状态的前端投影及临时 UI 状态；Rust 核心仍是业务状态的唯一真实来源。
- 页面和 feature 不直接调用 Tauri API，所有 `invoke` 和事件监听集中在 `ipc/`。
- 不使用 Mantine 或 React 组件直接执行 shell、访问 SQLite 或扫描文件系统。
- 主题通过平台 profile 和 CSS design tokens 调整，不复制三套业务页面。

### 6.3 共享应用外壳

所有桌面平台共享相同的信息架构：左侧导航区域、右侧内容区域、页面工具栏和可选全局状态栏。

```text
┌───────────────────────────────────────────────┐
│ 系统原生标题栏                                 │
├──────────────┬────────────────────────────────┤
│ 左侧导航区域  │ 页面工具栏                      │
│              ├────────────────────────────────┤
│ 下载         │                                │
│ 任务      2  │                                │
│ 历史         │           内容区域              │
│              │                                │
│              │                                │
│ 设置         │                                │
├──────────────┴────────────────────────────────┤
│ 可选：组件与全局任务状态                        │
└───────────────────────────────────────────────┘
```

- 下载、任务、历史为主导航项。
- 设置固定在导航区域底部。
- 任务导航项可以显示运行中数量 badge。
- 页面级主要操作放在内容区工具栏，不塞入全局导航。
- 首版保留系统窗口装饰，不自绘 macOS 交通灯或 Windows 窗口按钮。
- 默认窗口和可调整的最小逻辑尺寸均为 `1280 × 800`，允许放大；新建窗口生效，开发中需重启原生窗口确认。

### 6.4 平台 profile

平台差异通过 `PlatformProfile`、根节点 `data-platform` 和主题 token 表达：

三种桌面平台的侧栏尺寸统一：展开宽 `216px`、紧凑宽 `56px`、导航项最小高度 `34px`，沿用现有 macOS 几何尺寸。尺寸和选中风格来自同一个共享配置，切换平台预览不改变侧栏或右侧工作区位置；平台只保留字体、快捷键及文件管理器文案等差异。

```text
PlatformProfile
├─ sidebarWidth
├─ compactSidebarWidth
├─ navigationItemHeight
├─ selectionStyle
├─ systemFont
├─ revealFileLabel
└─ modifierKey
```

macOS 参考 SwiftUI `NavigationSplitView`：

- Sidebar 使用共享宽度 `216px`（紧凑 `56px`），导航项最小高度 `34px`。
- 选中项使用圆角浅色填充，不使用 Windows 左侧强调线。
- 字体使用 `-apple-system` 系统字体栈。
- 页面标题、工具栏、sheet 和设置入口遵循 macOS 习惯。
- 文件操作文案使用“在 Finder 中显示”。
- 快捷键使用 `Command` 修饰键，并支持 `Command+,` 打开设置。

Windows 参考 WinUI 3 `NavigationView`：

- Sidebar 与 macOS 使用相同尺寸，不再单独采用 `232px` 宽和 `42px` 导航高度。
- 选中项与 macOS 统一使用 10px 圆角和浅色强调底，不再使用左侧强调线；保留 Windows 字体与快捷键。
- 字体使用 `Segoe UI Variable`、`Segoe UI` 系统字体栈。
- 提示、确认和状态分别参考 `InfoBar`、`ContentDialog`、`ProgressBar` 的交互语义。
- 文件操作文案使用“在文件资源管理器中显示”。
- 快捷键使用 `Ctrl` 修饰键。

Linux 使用中性桌面风格：

- 侧栏与其他桌面平台共享 `216px`/`56px` 宽度及 `34px` 导航项最小高度，不再单独使用 `224px` 宽和 `40px` 导航高度。
- 导航选中项同样使用 macOS 风格圆角浅色底，图标强调色、文字可读性随明暗主题变化。
- 使用系统字体和普通不透明背景。
- 不默认模拟 Mica 或 macOS 毛玻璃。
- 文件操作文案使用“在文件管理器中显示”。

平台 profile 只改变表现、文案和快捷键，不改变下载状态机、数据模型或 IPC 协议。开发环境允许强制选择 profile，以便在 macOS 上检查三套视觉变量；切换入口仅在开发环境的顶部标题栏显示，避免遮挡右下方操作按钮。这不等同于完成 Windows/Linux 原生验证。

### 6.5 窗口与导航响应规则

| 内容宽度    | 导航形态                                   |
| ----------- | ------------------------------------------ |
| `≥ 960px`   | 完整图标和文字导航                         |
| `760–959px` | `56px` 紧凑图标导航，文字通过 tooltip 提供 |
| `< 760px`   | 不作为正式支持尺寸；由最小窗口宽度避免进入 |

这是桌面应用，不为首版增加移动式汉堡菜单或覆盖式抽屉。窗口缩放不能导致主要操作、进度或错误信息不可访问。

### 6.6 共享交互规则

- 设置页使用顶部五组分段标签：“通用、下载、网络与代理、Cookie 与登录、运行组件”，首次仍进入“下载”，随后在窗口会话内保留选中组；顶部标签固定在内容滚动区上沿，只显示当前组内容。内容最大宽 1100px，桌面最小窗口 1280×800 下全部标签同排，窄预览可横向滚动标签，不挤压换行。“隐私与诊断”不再独立占用 Tab，导出诊断信息保留在“通用”底部。未来尚未实现的关于/应用更新模块不创建空标签。
- “通用”管理界面偏好，名称区别于下载/网络等功能设置。主题为跟随系统、亮色、暗色；界面语言为跟随系统、简体中文、English，均默认跟随系统，即时生效。语言按系统偏好列表匹配已支持语言，中文变体使用简体中文，均不支持时回退英文；显式选择不被系统变化覆盖。主题跟随系统实时响应外观变化，语言监听系统 languagechange。HTML lang 与日期显示语言同步，不更改时区、文件名、视频标题、站点内容、字幕语言选择或原始日志。
- 非敏感 UI 偏好仅以 `{ theme, language }` 保存在本机 WebView 的 `savebeam.ui-preferences.v1` localStorage 键，不包含媒体、路径、Cookie、任务或页面草稿。启动校验枚举类型；不可读/损坏时明确提示并回退系统默认，不静默覆盖原值；用户显式选择后才保存修复。写入失败不应用新值、不伪报保存成功。其持久化与仍仅驻留内存的未保存表单/页面状态不同，不新增 SQLite schema。
- 界面文案使用本地中英词条，编译期/单元覆盖校验及参数占位符校验；不调用翻译服务。语言变化订阅只刷新显示，不按语言重建路由或页面实例、不重复网络读取或操作、不保存其他草稿。不可变媒体标题、URL、文件路径及原始工具输出仅作为原文参数展示。Rust 错误中文保留已脱敏具体上下文，英文按稳定错误码给出安全说明；后端返回的结果/站点说明不作任意机器翻译，已经产生的临时反馈可能保留产生时的语言。
- 设置页由 AppShell 在首次访问时创建一个窗口会话实例，后续切换侧边栏只隐藏，不卸载；返回保留选中的 Tab、各组未保存输入、错误/成功提示、进行中的保存/检测/安装及各组滚动位置，不隐式保存、重复读取或重新检测。首次进入设置前不挂载其表单，也不自动执行组件检测。面板使用 Mantine Tabs 的 display-none 保持实例，整页隐藏时不参与布局或键盘导航；滚动监听仅在设置活动时启用，其他页面滚动不能覆盖其位置。支持方向键切换、Home/End 定位和 Enter/Space 激活。各模块保留原有独立保存按钮、恢复及权限确认；草稿不写浏览器存储、文件或数据库，重载/关闭/重启后只读取已保存配置。未保存的默认值不用于新任务，任务仍读取已保存配置。
- 历史、订阅也在首次访问后各保留一个会话实例。侧栏或快捷键往返保留历史搜索输入及已提交查询结果，订阅链接草稿、显示已下载开关、展开/勾选、代理及高级选项、提示和各自外层/列表内滚动；导航本身不重复搜索、读取订阅目录或联网检查。新成品事件仍按历史上次提交的搜索条件刷新本地记录，不把未提交输入当作条件；重叠查询仅接受最新响应，删除后也维持原查询。订阅任务状态变化继续更新本地条目和可选历史系列，不重置范围或展开状态。历史搜索按钮和订阅检查按钮仍可显式刷新。
- 隐藏历史/订阅页不参与布局或键盘导航；删除历史、取消订阅和高级选项弹窗随活动页隐藏，返回继续原草稿，不自动确认操作或抢其他页面焦点。显式取消仍丢弃相应弹窗修改。订阅页收到新的显式来源链接时只回填输入，保留其他系列勾选/选项，不自动添加或检查；普通返回不重填。订阅全部检查离开后停止后续项，当前已发起项可完成并保存结果。以上会话仅在本次窗口运行期有效，重载/关闭/重启不恢复查询、勾选或弹窗草稿。

- 系列条目滚动条沿用原生 overflow 行为，仅在该区域定制样式：WebKit/Chromium 下为 8px 宽透明轨道、圆角细滑块，滑块配色适配明暗主题，悬停时提高对比度；其他引擎降级为标准 thin 滚动条。不隐藏溢出内容的滚动入口，不模拟滚动位置。条目与滑块之间保留间隔；空/短列表不需要滚动时不显示滑块，透明预留槽避免换行宽度跳动。列表可通过 Tab 聚焦并使用原生滚动键，滚轮操作保留在列表内。
- 滚动条轨道上下各内缩 4px，并设置圆角及透明背景，避免原生轨道的方形端部呈现截断感；滚到最顶部/最底部时滑块圆角应完整可见。视觉验收必须启用浏览器滚动条显示，不能用隐藏滚动条的截图代替。
- 系列解析仅公开前 50 项的原始序号、标题、视频 ID 和可选状态，提供逐项勾选、全选、取消全选。没有可选项时禁用开始；选择或下载模式改变后必须重新确认所选数量。空条目、重复序号、嵌套列表和越界项不可选，不把这些条目移除后重新编号。任务保存明确的序号数组，Rust 同时在创建与构造 argv 时拒绝空数组、重复、0、超过 50 的序号及数量不一致；仅生成固定数值的 `--playlist-items 1,3,5`，不回退成前 N 项。SQLite v8 保存数组，恢复和重试保持同一集合；旧任务没有数组时仍按原先的 1-N 范围处理。
- 单视频任务保存所选视频和音频的格式 ID 组合，以及 MP4/WebM/MKV 合并容器；仅音频任务尊重所选源音轨，再转换为 MP3。播放列表按每项自动选流，不复用某一项的格式 ID。
- 组件缺失不阻止进入应用；在用户首次解析或下载时展示安装引导。
- 缺少 yt-dlp 时阻止解析；缺少 FFmpeg 或 JS runtime 时按实际能力降级并给出说明。
- 任务阶段分别显示准备、下载、后处理和完成；FFmpeg 合并阶段不能继续显示为“下载中”。
- 已完成任务提供“打开文件”“打开所在文件夹”“查看历史”“重新解析”和“来源与版本”。文件操作从 SQLite 按任务 ID 精确读取成品记录，不依赖当前会话的 result 事件，重启后仍可使用；系列等多文件任务先选择目标文件，并将原始 outputIndex 与 taskId 交给现有后端打开命令，前端不传任意路径。记录已删除/保存失败时禁用文件操作并提示原因，仍可查看历史或重新解析；读取/打开失败显示任务局部错误，不假称下载失败。打开期间禁用重复操作。重新解析仅把完整原 URL 编码回填下载页，保留查询参数和 fragment，不自动解析、创建任务或覆盖文件，后续开始下载仍遵循全局重名策略；保留旧文件及新版本必须使用独立版本入口，见 9.6。
- 已完成、失败、已取消的任务提供“删除任务”及确认框，只从任务视图移除，保留历史、文件与订阅完成台账。排队/运行/取消中的任务必须先取消并等待终态，前后端均拒绝直接删除。SQLite v10 的 `hidden_from_tasks` 持久化删除状态，启动只恢复未移除任务，但底层记录继续供历史关联和订阅回填使用；不执行物理行删除，避免外键级联清空历史。数据库保存成功后才移除内存项；失败保留任务和确认框。删除事件与命令响应均同步前端，前端 tombstone 拦截已移除任务的迟到状态/进度/结果，防止旧快照让任务重新出现。重启仍不恢复已移除任务；清理历史或文件需前往历史页另行确认。
- 未知总大小使用不确定进度条，不显示虚假的 `0 B` 或百分比。
- 删除历史必须先确认，并提供默认不勾选的“同时删除下载文件”。未勾选时仅删除记录；勾选并确认后，仅将该记录明确列出的最终媒体文件移入系统废纸篓或回收站。字幕、封面、JSON 与保留的分轨文件尚未完整登记，不按文件名前缀扫描，不自动清理，也不删除任何目录。后端从数据库解析任务 ID，拒绝前端指定任意路径；全部预检原下载目录、规范路径及普通文件类型，拒绝符号链接、目录、路径逃逸和未完成任务，逐项操作前再次校验。文件缺失会跳过；移入失败不回退永久删除，保留记录并提示可能已有部分文件移入，支持重试。删除在后台执行，期间禁用重复确认和关闭确认框。macOS 使用原生 NSFileManager，恢复时可从废纸篓手动拖出。
- 单视频直接保存到设置中的下载目录，文件名为 `视频标题 [视频ID].扩展名`。视频 ID 使用 yt-dlp 提取的 `id`，而非格式 ID、分辨率 ID 或手工从输入链接截取：例如 B 站 `BV19wee6BEeP`，多 P 等情况保留解析器的子项后缀以避免重名，其他站点同理。字幕保留语言标识（如 `标题 [视频ID].zh-Hans.vtt`），JSON 使用 `标题 [视频ID].info.json`，封面使用同一前缀。未知 ID 省略整个后缀，不生成空方括号或 NA。
- 分类/系列视频保存到下载目录内的二级目录，采用 `系列名称 [系列ID]/序号-视频标题 [视频ID].扩展名`，序号使用系列中的原始顺序。目录 ID 优先 playlist_id、其次 series_id，缺失则省略，不把某一条视频 ID 当成系列 ID。系列标题缺失时依次使用 series/playlist 元数据，仍缺失则使用“未命名系列”；单个标题和序号缺失分别遵循 yt-dlp 的占位及序号 1。系列附属文件与各视频保持同一目录和序号标题，不在下载目录根部额外写入系列元数据。保留的分轨文件继承视频 ID，长标题缩短时优先保留末尾 ID。新规则仅影响后续下载，不批量重命名已有文件。
- 文件名中的路径分隔符与跨平台不支持字符交由 yt-dlp 文件名清理；同名文件遵循设置中的跳过或覆盖策略，默认跳过。
- 应用前台使用应用内通知，后台完成时才考虑系统通知，避免双重提醒。
- 首版不展示“暂停”能力，直到跨平台验证能够准确表达其语义。

### 6.7 前端状态划分

- 服务端状态：媒体信息、任务状态、组件状态，由 Rust 核心提供。
- UI 状态：当前页面、表单展开状态、筛选条件，仅保存在前端。
- 页面会话：AppShell 维护下载草稿身份和生命周期，DownloadPage 及详情 hooks 保持同一实例，最多一个下载工作区；设置、历史、订阅在首次访问后分别保留一个实例，不按访问次数或查询 URL 无限创建缓存，任务页仍使用普通路由。不同工作区只切换可见性，各自保存滚动/草稿，不持久化媒体 JSON 或临时选择；源信息可能过期，用户显式重新解析后更新。
- 持久化设置：由 Rust Repository 保存，前端不直接操作数据库。

```text

```

事件载荷必须包含 schema version，便于后续兼容升级。

IPC 协议约定：

- Rust 命令名使用 `snake_case`；命令参数沿用 Tauri 默认映射，Rust 侧为 `snake_case`、前端调用侧为 `camelCase`。序列化到前端的结构字段统一使用 `camelCase`。
- Rust 命令统一返回 `CommandResult<T>`。成功时直接返回 `T`，失败时由 Tauri 序列化 `AppError`，不再增加第二层 success/error envelope。
- `AppError` 使用 `{ code, message, retryable, diagnostic? }`；`code` 为稳定的 `snake_case` 值，`message` 可直接展示，`diagnostic` 必须先脱敏且不能代替用户提示。
- 事件名使用 `domain://past-tense` 或 `domain://noun` 格式，并集中定义常量，业务代码不得散落字符串字面量。
- 所有事件统一使用 `{ schemaVersion, payload }` envelope；首版 `schemaVersion` 为 `1`。

### 6.7 系列画质策略与逐项预检

- 采用“统一策略 + 少数条目单独覆盖”，而不是把一条视频的格式 ID 套用到整个列表。统一面板和单项弹窗均分为视频、音频两组。分辨率/FPS/音频码率可用 Best；四个源格式和编码字段默认显示“自动推荐”，分别优先 MP4、HEVC、M4A、AAC，不称作绝对最佳。两组可分别恢复默认，不影响另一组。
- 自动推荐是软偏好：先满足硬筛选，再优先高分辨率和名义 FPS，同档位才按 MP4、HEVC 偏好、独立分轨及上游排序选择；不为 HEVC 降低分辨率或 FPS。音频在有效候选中优先 M4A/AAC，再考虑容器兼容性与上游排序。无推荐格式/编码时可自动选其他候选，不标记为违反条件或跳过。手动指定的格式/编码仍是硬筛选。含音轨视频同样参与画质比较，不因分离流存在而忽略更高画质的一体流。
- 分辨率是指定档位，不再把 1080p 理解为“最高 1080p”。FPS 按名义值匹配，允许绝对差不超过 0.1（如 30 包含 29.97、60 包含 59.94）；未知 FPS 不能匹配指定帧率。编码按受支持的家族匹配（avc1/H.264、hvc1/HEVC、av01/AV1、vp09/VP9、mp4a/AAC 等），格式按源扩展名筛选；这些不是最终封装格式或转码指令。最终容器继续由实际音视频兼容性确定。
- 只筛选已有源格式，不压制码率、补帧或改变分辨率。指定条件无匹配时明确标记，默认跳过；只有勾选“无匹配时允许回退 Best”才忽略所有筛选条件并选择最佳可用组合，条目明确标识未满足条件。音频码率选项明确使用 `≤ N kbps`，码率未知不能当成符合上限。MP3 模式禁用视频条件，只筛选源音频，输出仍为转换后的 MP3，转换后大小不虚构。
- 旧任务的 `maxHeight`、`maxVideoBitrateKbps` 及 `allowExceed` 字段保留兼容语义，新建页面不再暴露视频上限字段；新增分辨率/FPS/格式/编码可空字段扩展现有 v12 策略 JSON，无需数据库迁移。`automaticRecommendations` 仅新建策略为 true，旧 JSON 缺失时为 false，保留旧上游排序。新旧任务均保留不可变快照，重启和重试不重新匹配或改写策略。
- 行末“单独设置”可仅覆盖该条目的策略，取消不应用，“恢复统一策略”移除覆盖。修改统一策略不会清空已有覆盖，但会取消批次确认；修改模式、勾选范围或单项策略同样要求重新确认。
- 初次 `--flat-playlist` 只用于快速拿到系列与原始顺序。B 站合集提取器可能只给 URL/ID，不保证标题或规格；随后自动通过 yt-dlp 元数据模式（`--no-flat-playlist --playlist-items --skip-download --ignore-no-formats-error`）补全，最多 50 项、每批最多 5 项，不下载媒体。可停止后续批次或重新读取；当前批次保留 60 秒及 JSON 上限防护。部分失败仍投影可用条目，失败/缺失/ID 改变明确显示，不等到下载再获取标题，也不把未知标题伪装为已读到。
- 详情返回只包含稳定 ID、标题、时长及最小格式字段，不传媒体直链、请求头或 Cookie。格式详情缓存在当前页面；策略变化只调用本地纯匹配逻辑，不再访问网站。更换链接/代理或重新解析后丢弃旧响应与单项覆盖；后台旧批次不回填到新链接。没有详情或匹配尚未完成时不能创建对应批次。
- `match_playlist_quality` 与 `start_playlist_download` 共用 Rust 匹配器，后者再次校验并生成每项独立任务，固定实际格式 ID（或音视频 ID 组合）、容器、原始序号、预期视频 ID、有效策略和高级设置快照。无需下载时重新挑选；重试保持快照，若源格式消失会明确失败，用户重新读取后可新建任务。原始序号与 ID 过滤避免列表重排后下载错项。
- 确认区显示匹配数量与将跳过数量；没有可下载组合不能开始。队列部分创建失败时返回已入队序号、任务、跳过项及错误，前端只移除已入队的选择，不重复加入；活动任务按系列 URL 和稳定 ID 拒绝重复。每项可分别取消/重试；并发、Cookie 授权、代理选择、文件命名、既有文件跳过/覆盖策略沿用既有设置。
- 参考：[yt-dlp 格式选择](https://github.com/yt-dlp/yt-dlp#format-selection)、[B 站列表提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py)。快速列表字段完整性由提取器决定，不把 `--list-formats` 当作可同时保证全部列表标题/格式的捷径。

### 7.2 下载引擎抽象

业务层不应散落 yt-dlp 命令参数。所有引擎调用通过统一接口完成：

```text
DownloadEngine
├─ inspect(url)
├─ start(options)
├─ cancel(task_id)
├─ validate_environment()
└─ engine_version()
```

首个实现为 `YtDlpProcessEngine`。接口存在的目的主要是隔离 yt-dlp 和业务层，而不是承诺首版支持多个下载引擎。

### 7.3 进程管理

`ProcessSupervisor` 负责：

- 为每个任务保存进程句柄和状态。
- 逐行读取 stdout/stderr，避免缓冲区阻塞。
- 将结构化进度转换成领域事件。
- 用户取消时终止完整进程树，避免遗留 FFmpeg。
- 应用退出时处理仍在运行的任务。
- 对异常退出、超时和不可识别输出提供统一错误。

首版不承诺真正意义上的“暂停”。yt-dlp 的断点续传和重新开始任务可以提供接近恢复的体验，但 UI 不应把取消后重试描述为无损暂停，除非经过跨平台验证。

## 8. 组件管理设计

### 8.1 必需组件

| 组件               | 用途                                                                        | 必需性               |
| ------------------ | --------------------------------------------------------------------------- | -------------------- |
| yt-dlp             | URL解析与媒体下载                                                           | 必需                 |
| FFmpeg             | 合并与后处理                                                                | 高质量音视频下载必需 |
| ffprobe            | 媒体信息检查                                                                | 推荐，与 FFmpeg 同源 |
| JavaScript runtime | yt-dlp JavaScript challenge 支持；Deno 优先，也可使用 Node.js、Bun、QuickJS | 完整站点兼容推荐     |

组件检测按 yt-dlp 官方 [EJS runtime compatibility](https://github.com/yt-dlp/yt-dlp/wiki/EJS) 检查最低版本：Deno 2.3.0、Node.js 22.0.0、Bun 1.2.11–1.3.14（已弃用）、QuickJS 2023-12-09；QuickJS-NG 版本不设下限。该兼容矩阵会随 yt-dlp 更新重新核对；系统包管理器提供的版本可能不满足此下限。

### 8.2 三种组件来源

```text
AppManaged  应用下载并管理
System      winget / Homebrew / apt 等管理
Custom      用户选择已有可执行文件
```

来源一旦确定，更新职责也随之确定：

- `AppManaged`：应用负责下载、校验、更新、回滚和删除。
- `System`：应用仅检测并展示更新命令，不覆盖系统文件。
- `Custom`：应用仅检测，用户自行维护。

### 8.3 应用管理安装

- yt-dlp：使用其官方 GitHub Releases。
- JavaScript runtime：应用管理方式默认安装 Deno，并使用其官方 Releases；系统或自定义方式可复用 Node.js、Bun、QuickJS。
- FFmpeg：Windows/Linux 使用 FFmpeg 官网各平台下载入口列出的可信构建提供者；macOS 不提供应用管理下载，使用 Homebrew/system installation，或由用户指定 `ffmpeg` 与 `ffprobe` 可执行文件路径。
- 下载地址和哈希来自受签名保护的组件清单。
- 清单使用带 schema 版本的 JSON，Ed25519 签名覆盖稳定结构化 payload；发行公钥固定在应用中。正式发行前必须配置发行私钥及轮换流程，开发测试密钥不能用于生产。
- Savebeam 清单以 `components.json` 作为 `coopsrc/savebeam` GitHub Release 资产，客户端固定读取 `https://github.com/coopsrc/savebeam/releases/latest/download/components.json`；仅接受 HTTPS 和 GitHub Release 资产主机重定向，清单上限 256 KiB。
- 打开组件设置页只检测本机版本，不自动请求发行目录；在线 Release 检查由“检查组件更新”明确触发。安装与更新由用户逐个点击启动，展示下载进度并允许取消。清单不可用时保留手动安装指引。
- 本机探测错误、组件操作错误、在线目录错误分别保存和展示。完整的四项组件均可用才显示全部可用；缺项或异常显示数量和具体状态，本机读取失败保留上次结果并注明当前未确认，不复用旧的成功摘要。在线错误以独立、可关闭的提示说明只影响应用管理安装/更新，不否定已可用的本机组件；本机重测不伪造在线恢复。在线重试立即清空旧发行包，失败后不能继续安装过期展示；空目录明确说明没有适用包，不宣称本机组件已是最新版。
- JavaScript runtime 的前端规范名称为 `javascript_runtime`；组件状态和发行目录在 UI 边界兼容 Rust 历史拼写 `java_script_runtime`。Rust 接受两种输入，仍保留历史序列化字节，避免改变既有组件清单的签名载荷。名称、许可证、自定义路径/安装操作统一使用规范前端键。
- Ed25519 私钥仅保存在 GitHub Actions Secret `SAVEBEAM_COMPONENT_MANIFEST_SIGNING_KEY`，绝不进入应用包或源代码；应用只包含公钥。密钥轮换时先发布包含新公钥的应用版本，再切换清单签名密钥。
- 下载到临时文件，校验通过后再原子移动到组件目录。
- 新版本通过 `--version` 和基本能力测试后才切换为当前版本。
- 至少保留一个上一版本用于回滚。

FFmpeg 页面入口（用于 Windows/Linux 应用管理候选及各平台手动安装指引）：

- Linux：<https://ffmpeg.org/download.html#build-linux>
- Windows：<https://ffmpeg.org/download.html#build-windows>
- macOS：<https://ffmpeg.org/download.html#build-mac>

Windows/Linux UI 应表述为“从 FFmpeg 官网列出的构建来源下载”，并展示实际构建提供者，不应把第三方构建描述成 FFmpeg 项目官方编译的二进制。macOS 仅检测 Homebrew/system 安装或用户指定路径，不从 Savebeam 组件清单下载 FFmpeg/ffprobe。

### 8.4 系统包管理器

手动安装建议跟随共用桌面平台自动识别及开发预览平台切换，明确显示当前平台/包管理器，命令、复制内容、平台说明与 FFmpeg 官网对应平台锚点同步变化。macOS 使用 Homebrew，Windows 使用 WinGet，Linux 当前明确标注 Ubuntu/Debian apt-get 示例，不宣称通用于所有发行版；Linux 的 Deno 仅提供官方安装说明，不虚构官方 apt 源。复制状态关联组件与具体命令，换平台后不沿用旧命令的“已复制”提示。此模块不运行安装命令，不收集管理员密码，也不改变组件路径或安装来源。

- Windows：winget。
- macOS：Homebrew。
- Ubuntu/Debian：apt。
- 其他 Linux：当前提示使用对应发行版包管理器；后续可根据 `/etc/os-release` 提供发行版专用说明。

应用不收集管理员密码，也不静默执行 `sudo`。首版提供命令展示、复制、打开终端和重新检测。系统仓库版本可能过旧，必须执行最低版本和能力检查。

### 8.5 查找顺序

自定义组件路径按组件分别保存在 SQLite `app_settings` 的 `component.path.*` 键，复用当前 schema；指定时验证并保存规范绝对路径，保存失败不改变有效配置。“自动检测”删除对应键，重启仍生效。启动时先绑定组件设置数据库，再恢复队列；检测、解析和下载都读取同一持久化配置。已指定的文件失效时保留来源和路径并显示不可用，不静默回退到其他可执行程序；用户需重新指定或显式恢复自动检测。数据库或设置读取失败明确报错，不用空配置掩盖失败。

1. 用户明确选择的自定义路径。
2. 应用管理的当前版本。
3. 系统常见安装位置。
4. 当前进程可见的 `PATH`。

macOS 从 Finder 启动时不能假设继承交互式 shell 的 PATH；Windows 包管理器安装后也可能需要重新启动应用才能读取新环境。

## 9. 下载工作流

### 9.1 媒体检查

```text
用户输入 URL
→ 前端执行基础格式检查
→ Rust 进行 scheme/长度/策略校验
→ ComponentManager 检查环境
→ yt-dlp 输出 JSON
→ Rust 过滤并转换为 MediaInfo
→ 前端展示媒体与格式
```

### 9.2 下载任务

```text
用户提交 DownloadOptions
→ Rust 再次验证所有字段
→ 创建任务记录
→ 启动 yt-dlp
→ 接收结构化进度
→ 通过 Tauri Event 更新 UI
→ FFmpeg 后处理
→ 验证输出文件
→ 写入历史记录
```

### 9.3 任务状态

```text
Queued
Preparing
Downloading
PostProcessing
Completed
Failed
Cancelling
Cancelled
```

状态转换由 Rust 核心控制，前端不能直接修改任务状态。

### 9.5 持续更新系列的本地订阅

- 左侧增加“订阅”，快捷键为平台修饰键 + 4，保留既有 1–3 和设置快捷键。下载页解析系列后提供“订阅此系列”，只预填订阅页链接，不自动订阅或下载。订阅页可从已完成的系列任务添加，也可填写系列 URL；相同规范化 URL 不重复添加。
- 所有状态保存在本机 SQLite（订阅结构在 v9 引入，当前 v17）：`subscriptions` 保存系列 URL、来源 ID、标题、上次成功检查时间及不完整标记；`subscription_entries` 以订阅与视频 ID 为键保存原始序号、标题、可用、首次检查后新增、已下载状态，v14 新增可空时长；`downloaded_media` 独立保存已完成 ID，不依赖用户是否删除历史。任务保存 `expected_media_id`，序号数组为 u32，但普通下载仍限制前 50 项；v11 的 `use_proxy` 仅保存是否使用代理，v12 增加可空 `quality_policy_json` 保存有效画质策略，v15 的可空 `playlist_part_json` 保存合集内分 P 上下文；v16 增加仅用于列表分组的 `group_json`，不复制代理地址或媒体直链。
- 首次订阅建立已知条目基线，不将它们全部标记为已下载，也不将它们误标为后续新增。已有的逐项完成记录优先使用；旧版本历史只在最终成品仍存在、文件名 stem 精确以 ` [视频ID]` 结尾时辅助识别，不按标题或序号推测。没有 ID 的老文件仍显示待下载。删除历史或取消订阅不清除完成 ID；“已下载”表示曾成功保存，不保证文件一直存在。
- 检查由用户主动触发，可检查单项或全部；没有后台定时轮询、云端服务、推送或自动下载。全部检查串行显示进度，可停止后续检查，离开页面也停止后续项；当前项最多约 60 秒。继续使用设置中的全局 Cookie 授权，不增加浏览器 Cookie 读取权限。应用在未打开时不检查更新。
- 普通解析保持读取最多 51 项、展示前 50 项。订阅专用 flat-playlist 扫描读取最多 1001 项，保存最多前 1000 项，最多 100 个订阅；进程超时与 16 MiB JSON 上限不变。超限、总数未读全、缺失稳定 ID 或重复/异常条目时提示检查不完整，不宣称整个系列没有更新。B 站多 P URL 的稳定 ID 仅在已验证的 bilibili.com `/video/BV…?p=N` 形式下按提取器约定映射为 `BV…_pN`；其他站点要求提取器返回稳定 ID。不承诺所有站点的 flat ID 与最终 ID 都兼容。
- 同一个视频 ID 的重排、标题变更不算新增。完整检查可以将移除条目标为不可用，但保留完成状态；不完整检查不将范围外条目推断成已删除。失败保留上次结果及检查时间，页面展示错误而非清空或显示“无更新”。取消订阅需确认，只删除订阅及其列表，不删除文件、历史或已经排队的任务。
- 新增、待下载、已下载分开展示；条目默认折叠、展开后独立滚动，支持“选择新增”、选择待下载、逐项勾选及取消，单次最多 50 项。下载前重新检查并按 ID 找到最新序号；一项一个队列任务，自动选择视频和音频合并，沿用当前默认目录、重名策略和系列文件结构，不隐式继承旧任务的音频/字幕等附加选项。
- 活跃任务中的相同条目不重复入队；整系列普通下载进行中也拒绝订阅重复下载。仅订阅内部任务可使用 1–1000 的单一序号，并持久化精确目标 ID。普通 `start_download` 清除外部传入的 ID guard，不能据此绕过前 50 项上限。guard 使用逐字符 Unicode 十六进制编码的 yt-dlp 固定 `--match-filter` 精确正则，ID 无法注入过滤器表达式。排队期间列表变化时拒绝错误 ID，不下载替代视频，用户需重新检查和选择。
- 所有下载额外输出最小 `after_move` ID/最终路径投影，不保存媒体 URL、请求头或完整解析 JSON。仅在进程成功、非空成品存在且位于下载目录内、ID 对应独立验证过的最终路径时登记完成；订阅任务还必须匹配唯一预期 ID。排队、失败、取消不标记已下载；普通批量任务发生部分失败时保守地不登记本批 ID，可在下次检查时凭成功历史辅助识别。部分入队失败会返回已创建任务和错误，不丢弃已入队结果。
- 订阅页面使用后端编写的安全上下文文案表达“列表变化/重复任务”等原因，不展示 diagnostic 或原始 stderr。英文翻译、自动定时检查、大于 1000 项的分页遍历以及真实站点跨平台兼容性另行验证。
- 不把 flat-playlist 缺少的标题伪装成视频实际名称：空值及旧的“未命名视频”在 UI 显示“标题待补全”。展开条目或对已展开系列检查更新后，按最多 5 条一批读取完整元数据（skip-download），自动补全最多 50 条缺失标题，同时保存时长。更大列表可显式继续，标题已知但时长未知时也可主动补全；不一次深度解析全部 1000 条，不下载媒体/附属文件。已缓存信息可直接显示，检查返回缺失标题/时长时保留旧值，不修改完成台账或上次检查时间。
- 元数据补全使用系列检查同一套全局网络与 Cookie 授权，不复制 Cookie 到数据库。前端跨展开列表串行，后端独立互斥；与检查/下载并发时，数据库仅更新仍存在、可用且视频 ID/原序号匹配的条目，重排、取消订阅或身份变化不能错配/复活旧行。只投影标题和有限时长，不返回/保存媒体直链、头或格式列表。读取失败保留原信息，用户重试后才重新读取失败批次。
- 收起列表或切换侧栏停止后续批次，当前批次最多约 60 秒，完成后仍可保存匹配结果；返回保留勾选、读取预算、进度和滚动位置，不因路由往返重置 50 条自动预算。阅读/下载无联动，不产生隐式任务；下载尚未补全标题的条目时任务名称至少包含视频 ID。补全后的标题进入既有任务展示，最终文件名仍由下载时 yt-dlp 的实际标题决定。
- 订阅条目使用独立 Mantine ScrollArea，最高 320px，纵向轨道透明、上下均内缩 6px，滑块完整圆角，避免 macOS 原生方框轨道端部的截断观感；键盘、滚轮和拖动均沿用正常滚动交互。仅替换订阅条目容器，不改变侧栏/内容区及下载页滚动。视觉验收覆盖顶部和底部，不能只截图列表中间或隐藏滚动条。

### 9.6 来源变化提示与历史版本

订阅列表仍按父视频展示；包含分 P 或需要逐项画质时，通过“选择画质与分 P”进入下载页勾选。快速批量入口不自动拆分分 P。已完成 P 按原合集 URL 和子 ID 登记，全部已知 P 完成后才登记父视频；只完成一个 P、失败或取消不能把整项标记已下载。活跃分 P 与父视频下载相互防重。

- 历史记录、已完成任务共用“来源与版本”弹窗；打开只读取本地版本，旧记录首次按已有成品计算摘要。主动“检查来源变化”才访问站点；默认直连，可勾选使用已配置代理，Cookie 继续使用全局明确授权。无自动检查、自动重下或云端服务。隐藏历史页时弹窗一并隐藏，返回保留状态；新版本完成后可点击“刷新版本”读取本地结果，不触发站点请求或抢侧栏导航。
- 新成功任务记录完成时的最小来源观察：媒体 ID、extractor key、整数秒时长、可用修改时间、B 站 cid，以及排序去重后的源格式白名单摘要。格式只投影 ID、扩展名、音视频编码、尺寸、FPS、精确 filesize；不比较标题、临时 URL、请求头或完整 JSON。不具备这些字段时不推断它们的值。观察表示任务完成时可见元数据，不证明站点提供了与本地文件逐字节对应的版本；跳过已有文件或站点格式列表变化也可能影响判断。
- 比较明确区分“无法判断”“疑似来源发生变化”“未发现明显元数据变化”和“媒体标识已改变”。缺少旧基线时不使用今天的来源信息冒充历史；同 ID 的时长、修改时间、cid 或源格式摘要变化只提示疑似，不证明 UP 主换源。媒体标识/extractor 或系列预期 ID 改变时，拒绝沿用旧版本链下载，要求重新解析确认。无法访问来源则报错，不当成没有变化。
- 用户检查后可显式“重新下载并保留旧版本”；后端会重新检查而非信任前端结果。首版针对单视频及一项一任务的系列/订阅；旧的多媒体批量任务仅可看本地记录，重新下载需按单项重新解析。按原单一序号解析系列详情，支持订阅范围内 1–1000 的历史位置；普通创建/估算前 50 项边界不变。系列重排到不同 ID 时不下载替代条目；单视频检查明确使用 no-playlist，与其下载模式一致。
- 新任务沿用原高级选项和有效画质策略；旧任务无策略时使用自动推荐。重新匹配当前可用格式，不复用过期格式 ID，无法匹配则要求重新解析调整。代理选择写入新任务快照，Cookie 来源不写入任务。原文件不移动、不改名、不覆盖；新输出放在原根任务下载目录的 `Savebeam Versions/根任务ID/v-唯一标识/` 内，内部仍使用既有单视频/系列命名。新任务强制 Skip，隔离于全局覆盖选项；重试/重启沿用同一新目录、原序号、ID guard、策略和高级快照，失败不丢旧文件。
- schema v13 在任务中新增可空 `version_parent_task_id`，普通创建清除外部传入的关联；`media_versions` 保存根/父任务、版本序号、完成时间、最小来源观察和每个成品的路径、字节数、SHA-256。重新保存同一任务不新增版本序号。删除任务视图不删除这些信息；删除某条历史时事务删除该条版本元数据，其余版本及订阅完成台账保持不变。文件删除仍仅按原确认框处理该条成品，绝不扫描、递归删除版本目录。
- 文件摘要按 64KiB 缓冲流式计算，核对下载目录和普通文件，拒绝缺失、越界和叶节点符号链接；Unix 以 O_NOFOLLOW 打开并核对 inode，文件大小/修改时间变化或取消则不采用摘要。读取失败显示摘要不可用，不用文件名或大小冒充内容相同。只对单成品与父版本摘要比较；字节相同/不同不等于来源相同/不同，编码、封装和嵌入元数据均可能影响结果。完成摘要检查后才登记系列成功 ID。
- 显式版本读取/检查/创建共享最多一个后台操作，避免重复元数据进程和旧成品哈希。来源行上限 128KiB，普通进度/完成行仍为 16KiB；来源超过上限会丢弃其观察，不影响独立的完成 ID/路径记录。仍遵循既有进程超时、JSON 限额和安全错误约定；真实站点及 Windows/Linux 原生验收另行执行。

### 9.7 任务和历史的合集分组

- 同一系列合集或独立多 P 视频在任务、历史各显示一条可展开的分组；后续补下、订阅更新及版本重下合并到同一来源组。普通单视频仍独立显示，不按相同标题或文件路径猜测归组。成功任务不在任务页显示；整组无未完成任务时离开任务页，成功记录仍在历史页。补下或更新有新未完成项时原组重新出现在任务页，完成后再次离开；失败/取消项保留以便重试。
- 任务保存可空的 `DownloadGroup { key, title, sourceUrl, kind, itemIndex, partIndex }`。Rust 由明确的合集来源生成并校验稳定键；Bilibili 合集按空间路径及 sid、多 P 按父 BV，YouTube 播放列表按 list 归组，忽略已知跟踪参数和单项选择参数。未知站点保守保留路径/有效查询及 fragment，不跨域合并。父名称仅为显示，改名不创建新组；源格式、序号选择、文件输出与完成登记仍使用原始任务上下文。
- 任务摘要显示本轮子任务数、已完成/进行中/失败/取消数量，进度按完成条数统计，不冒充字节传输进度。schema v19 增加可空 `batch_id`：一次合集/分 P/订阅提交共用批次，普通下载和手动新版本使用独立批次，重试和恢复保留批次。稳定来源分组不变，进度只计仍有未完成项的批次及其已完成兄弟项；已全部完成的旧批次不计入新下载，即使历史或旧文件被删除。多个未完成批次仍合并一张卡片。旧记录缺少批次时只将未完成任务纳入恢复批次，不推测旧完成记录的归属。历史摘要显示当前记录数、最近完成时间与大小之和；搜索匹配组名、子标题或路径，筛选后明确为当前结果数量。展开后按原始项/P 序号排列，各版本保留独立记录。
- 分组不创建额外父下载进程、不合并历史行或实际文件。两页共用封面、标题、摘要及操作区样式；任务另有进度，历史无进度。两页分组均提供“选择视频”，回填原来源到现有下载工作区，由用户选择网络、解析最新列表/画质并重新勾选，不直接重复整组下载。
- 任务子卡片分行显示所选视频的分辨率、FPS、编码、码率和预计容器，以及音频的编码、码率和源格式；格式 ID 仅放在悬停说明，不作主要文案。schema v20 为任务增加可空 `format_details_json`，只保存有限、与语言无关的参数，不含直链、请求头、Cookie 或完整格式列表。单视频保存解析时的实际选择，合集/多 P 由匹配器提取对应轨道，版本重下重新捕获当前匹配，排队、取消、重试和重启保留。MP3 明确分开输出格式与源音频参数，不把源 AAC 码率冒充转码后 MP3 码率。自动选择任务显示下载时确定；缺少快照的旧任务明确提示未保存，不凭站点数字 ID 推测参数，不因查看任务而自动联网。展示快照不参与 yt-dlp 参数构造。
- 分组支持“删除整组”：打开确认框从 Rust 获取完整成员快照，历史搜索只命中部分条目也不缩小删除范围。确认提交明确成员 ID 与组键，后端预校验所有归属、去重及每次最多 1000 项，不接受任意文件路径；确认后的新增项不在范围内。任务删除先向整批发取消，再等待最多 15 秒停止后软隐藏，已经成功完成的项保留历史。历史默认仅删记录（含各版本），可勾选按既有规则将关联媒体移入回收站，不删目录、附属文件或订阅完成台账。部分失败显示已完成数量，剩余记录保留以便重试，不伪报全组成功；单项操作仍保留。
- schema v16 为任务增加可空 `group_json`，创建后随排队、恢复、重试与版本复制保留。旧任务只凭已持久化的 playlist/分 P 上下文归组；缺少父名称时使用来源链接，无法确认的普通旧单视频保持独立。迁移不访问网站，不重写原输出路径或执行选项，也不把新读取的名称伪装成历史信息。

### 9.8 卡片封面缓存与信息刷新

任务/历史及其合集卡片优先读取本地记录，切换页面不主动联网。标题、来源、实际选择、版本信息、成品路径、大小和完成时间继续由既有 SQLite 记录保存；订阅标题/时长沿用既有缓存和显式检查更新。下载时的快照不因查看或封面刷新而改写。

schema v17 新增 `record_artwork` 与 `task_artwork`。下载页将已经解析的栅格封面随创建提交；任务和缓存引用同事务保存。相同 data URL 按 SHA-256 去重，补下可复用同组缓存，版本任务继承原任务封面。封面不进入实际 yt-dlp argv，不复制进排队/重试工作参数；读取任务列表和历史列表也不批量返回图片，卡片进入可见区后才按任务 ID 读取。

封面缓存评估与采用的策略：

| 内容                                    | 本地策略                                                                                                                         | 更新时机                                                            |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 封面                                    | 缓存图片本体，避免远程防盗链和地址失效；只接收 PNG/JPEG/GIF/WebP/AVIF，校验前缀、签名及解码后 4 MiB 限额，拒绝 SVG/HTML/任意 URL | 解析创建时保存；卡片可主动读取/刷新，失败保留旧缓存                 |
| 已下载记录与版本信息                    | 长期保存历史快照，不用当前来源覆盖旧版本                                                                                         | 新任务完成后新增；用户显式删除                                      |
| 合集条目、标题及字幕/画质列表           | 下载草稿保留会话缓存；订阅条目沿用数据库缓存                                                                                     | 用户重新解析、重新选择/读取详情或检查订阅更新；下载前仍核对媒体身份 |
| 媒体直链、请求头、Cookie、完整原始 JSON | 不作为长期缓存                                                                                                                   | 沿用原有组件/登录和即时解析流程                                     |

缓存容量按数据库图片文本合计限制 64 MiB，超过时按最近使用时间移除最旧图片及缓存引用，不删除任务、历史、版本或用户媒体。无封面或缓存被回收时显示占位和读取按钮，不隐式联网恢复。显式刷新使用原任务的网络选择和已授权全局 Cookie，仅请求媒体信息及图片；不下载视频，不自动重建任务或刷新历史版本基线。当前不增加后台定时联网刷新；需要持续更新的合集仍由订阅检查承担。

schema v18 独立添加缓存 `last_used` 时钟，兼容开发期间已经添加该列的 v17 数据库，保留其值；缺少时以 0 初始化。v19 增加任务批次字段，当前 v20 增加所选音视频参数快照，不改变既有缓存。已应用的迁移不能通过修改同一版本 SQL 来升级用户数据库。数据库无法打开时保持原文件与错误，不自动清空任务/历史，恢复前不得删除 WAL/SHM。

## 10. 数据与隐私

### 10.1 SQLite 数据

计划保存：

- 用户设置。
- 下载任务与最终状态。
- 下载历史、标题、来源 URL、输出路径和完成时间。
- 已知组件版本、来源和安装路径。
- 下载默认目录、文件冲突策略和最大并发数（限制为 1–4）。
- 全局下载选项在 `app_settings` 的 `download.option_defaults` 保存，读取与保存均校验，不含 URL、Cookie 或代理。高级选项使用既有任务列保存扁平快照；v12 新增系列策略 JSON，旧任务为 NULL，既有格式和选项不重写。
- 媒体网络模式与不含认证信息的自定义代理地址。
- 系列订阅、条目原始序号与稳定视频 ID、成功检查时间和逐项下载完成台账。
- 来源变化观察、历史版本关联与最终成品 SHA-256（v13）；不保存媒体直链、完整解析 JSON 或 Cookie 内容。

应用启动恢复策略：排队、准备、下载及后处理中的任务按原快照恢复队列；正常退出停止进程但不把任务写成用户取消，退出后的迟到进度/取消/失败不能覆盖待恢复状态，已验证且保存历史的成功结果仍可提交完成。用户主动取消中的任务恢复为已取消，失败/已取消仍由用户手动重试。保留部分文件，由 yt-dlp 按其续传能力处理，不承诺跨站点无损恢复。

对仍有未完成项的批次，启动时核对其中已完成条目登记的成品：实际文件存在、非空、位于原目录内且已知总字节数相符才保持完成；缺失且本批正恢复运行则重新入队，同时清除对应订阅完成标记（分 P 包括该子 P 及父项，不清除其他 P）。仅剩失败/取消的批次不自动启动。无可用成品记录的活动批次条目重新入队；非普通文件、符号链接、大小改变、越界或无法访问则转为失败，供用户检查后重试。检查不扫描目录、不读取媒体内容、不删除或移动文件，也不把同大小文件当作内容完整性的证明。

全部完成的批次进入历史后，缺失文件不触发自动下载、不改变原完成状态。历史页及折叠组卡片检查已登记路径，显示“文件已删除”或“文件不可用或无法访问”；返回历史、下载完成或点击“刷新文件状态”重新检查本地状态，不访问网站。缺失/不可用条目提供“重新下载”，显式点击后通过既有来源身份核对与画质重新匹配创建新版本、使用独立版本目录，保留旧历史和文件路径，防止同条目的活动下载重复创建；旧式多成品历史仍要求重新解析为单项。不因查看历史或删除文件而自动联网。

默认不保存：

- Cookie 内容。
- Authorization header。
- 带临时签名参数的媒体直链。
- yt-dlp 完整未脱敏日志。

### 10.2 Cookie策略

默认情况下 Savebeam 不使用登录 Cookie。用户可在“设置 → Cookie 与登录”中配置 `cookies.txt` 或浏览器配置；该授权全局用于媒体信息解析和下载，方便需要登录或提供更高画质格式的网站。用户可随时清除来源并撤销后续调用授权。具体约束：

- 不复制 Cookie 内容到数据库；仅在应用设置中持久化文件路径/浏览器类型和明确的用户授权状态，不将来源信息写入下载任务。
- 不写入普通日志。
- UI 明确说明敏感性和账号风险。
- 传给 yt-dlp 后不产生额外永久副本。
- 用户必须在设置页选择来源并明确勾选全局授权后，才允许 yt-dlp 在解析和下载调用中使用 `--cookies` 或 `--cookies-from-browser`。
- Savebeam 不自行枚举或读取浏览器数据；由 yt-dlp 在本机读取所选浏览器配置，配置选择遵循 yt-dlp 默认规则（通常为最近使用的配置）。UI 必须提示这会使用用户账号权限发起请求，且可能需要先退出浏览器。
- `cookies.txt` 与浏览器来源互斥；选择文件时使用原生文件选择器，不读取或复制文件内容，只向 yt-dlp 传递路径。
- yt-dlp 的 `--cookies FILE` 会读取并可能写回 Cookie jar；UI 必须提醒用户它可能更新所选文件，并建议不愿修改源文件时选择其副本。

### 10.3 日志脱敏

至少过滤：

- `Cookie`、`Authorization` 等 header。
- URL query 中的 token、signature、key 等字段。
- 用户主目录的完整路径；当前版本始终脱敏，不提供保留路径的选项。

目前错误诊断统一经 `security::redaction` 脱敏后才进入 IPC；敏感 header 整行移除，敏感 query 参数值替换为 `[REDACTED]`，当前用户主目录替换为 `~`。yt-dlp 原始 stdout/stderr 不写入持久日志或诊断文件。

设置页的“导出诊断信息”必须经用户确认和系统保存对话框。当前导出为本地 JSON 报告，只包含应用版本、OS、CPU 架构和任务状态计数，不包含 URL、标题、Cookie、错误原始输出或任何文件路径，也不会自动上传。用户选定位置后应用才写入文件。

### 10.4 媒体网络与代理

共用 `NetworkPreferences { proxyMode, proxyUrl }` 保存在 SQLite `app_settings` 的 `network.preferences`。设置默认使用默认网络（用于订阅检查及旧任务），不读取/导入用户浏览器代理，不修改系统设置：

- 默认网络：不添加 yt-dlp 的 `--proxy`，不覆盖工具/网络库的默认代理行为（例如环境变量）。GUI 不保证继承终端环境；连接失败时建议显式填写代理。
- 直连：传递两个独立 argv `--proxy` 与空字符串；封面客户端使用 `no_proxy()`，禁用该类请求的环境代理。
- 自定义代理：传递 `--proxy` 和已校验地址，封面客户端关闭默认代理后使用同一地址；启用 reqwest 的 SOCKS 支持。支持 `http`、`https`、`socks4`、`socks4a`、`socks5`、`socks5h`，含 IPv6 主机。显式写端口更清楚；HTTP/HTTPS 和 SOCKS 未写端口时由协议默认值处理。

Rust 在保存、读取设置以及生成进程参数/封面请求时重新校验。自定义地址最大 2048 字节，允许清理首尾空白；拒绝内部空白/控制字符、反斜杠、非法或零端口、非代理协议、路径（根路径除外）、查询参数、fragment 和 userinfo。首版不支持账号密码，避免在 SQLite 和进程 argv 中明文保存认证信息。错误提示不回显输入和 URL 解析器原始错误。改为非自定义模式会清空自定义地址；损坏设置或失效代理不由 Savebeam 静默改为直连，可在 UI 中明确重试读取或恢复默认网络。

新建下载默认不勾选“使用代理”，解析 IPC 缺少选择也按直连处理；Rust 始终显式传 `--proxy` 空字符串，封面使用 `no_proxy()`，即使全局为自定义或环境变量设有代理也不使用。勾选后要求设置已保存自定义代理；缺少配置、损坏或失效时明确失败，不降级直连。下载页在切换选择时清除解析与大小缓存，并丢弃旧响应，重新解析后再下载；解析与封面使用同一份有效网络配置，大小估算和下载使用同一布尔选择。订阅页批量下载同样提供该选项，下载前的条目复核也使用此选择；独立的订阅添加/检查仍沿用全局模式。

SQLite v11 的任务字段 `use_proxy` 为可空布尔：`false` 强制直连、`true` 使用启动时最新自定义地址、`null` 仅兼容升级前任务的全局继承行为。普通新建 IPC 未传选择会转换为 `false`；新订阅下载亦默认 `false`。重启恢复及重试保留选择；勾选任务启动时若自定义模式被取消，会报配置错误，不静默切换网络。地址变更不影响已启动子进程。代理地址/凭据不复制进任务和历史，不进入导出诊断。组件下载与应用更新维持原网络行为，当前代理不是全系统代理，亦不承诺覆盖用户额外配置的外部下载器。

保存设置只做格式校验，不自动连通 YouTube 或读取 Cookie，也不增加后台探测请求。用户可显式点击“测试连接”，使用当前填写（可未保存）的配置，结果只保留在本次界面。自定义代理先进行 3 秒上限的 TCP 端点测试；成功仅代表端口可连接，不代表协议或转发可用，失败时跳过 YouTube 检查且不回退直连。默认网络/直连模式跳过独立代理端点检测。

YouTube 检查固定请求 `https://www.youtube.com/generate_204`，8 秒总超时，验证 TLS，不携带 Cookie/Authorization，不跟随重定向、不读取响应正文或下载媒体。只有预期 HTTP 204 显示通过；200、重定向、403、429、5xx 等显示已收到响应但受限/异常，不判为可正常访问；DNS/TLS/请求错误或超时单独标记失败。代理端点与 YouTube 结果分别展示状态和请求耗时，不能把端口开放说成代理完全可用，也不能把非 204 响应说成端点不通。进程内只允许一个连接测试，测试时锁定编辑/保存/重置，修改配置或保存后清除旧结果。IPC 不接受自定义检测 URL，不读取/改写持久化设置，不生成诊断日志或后台定时任务。

代理不能解决登录、站点限制、格式可用性或 JS runtime 缺失；UI 不以“保存成功”或连通性通过代表所有 YouTube 视频一定可下载。测试所用网络库与 yt-dlp 并非同一实现，仍需实际解析/下载验收。`--proxy` 的直连语义与协议依据见 [yt-dlp 官方网络选项](https://github.com/yt-dlp/yt-dlp#network-options)。

## 11. 安全设计

- 媒体页面仅允许 `http` 和 `https` URL；代理端点独立按 10.4 校验。本地文件导入属于未来独立功能。
- 限制 URL 和文件名长度。
- 输出路径必须经过规范化和允许目录检查。
- 下载组件时验证 TLS、固定来源、架构和哈希/签名。
- 解压组件时防御 Zip Slip 和符号链接逃逸。
- 不执行从 yt-dlp 输出、媒体标题或远端元数据中得到的命令。
- Tauri CSP 默认仅允许打包本地资源、Tauri IPC 与本地 Vite 开发服务器；不加载远程脚本，内联样式仅因 Mantine/React 动态样式保留 `unsafe-inline`。
- 主窗口 capability 只允许事件监听/取消监听和确实使用的原生文件/消息对话框；不启用 shell、filesystem、process 或前端 opener 通用权限。
- React 错误提示使用稳定错误码对应的 locale catalog，当前界面仍默认简体中文；新增语言时扩展 `src/i18n/`，无需改 IPC 错误结构。
- 任务状态和下载进度提供屏幕阅读器语义；异步错误通过 alert 区域播报，操作状态通过 status 区域播报。

## 12. 开源许可证与内容合规

### 12.1 组件许可证
