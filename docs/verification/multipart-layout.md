# 多 P 类型与双栏布局

2026-10-23，macOS 开发环境。

## 实现

- 区分 single / multipart / collection；Bilibili 独立多 P 使用可信父 BV、页面及 P 身份核对，不把短列表误判为多 P。
- 独立多 P 也使用宽卡片双栏：左侧媒体信息和共用画质；右侧 P 列表。画质与系列复用同一表单，直接展示分辨率、FPS、视频格式/编码、音频格式/编码/码率及回退选项，无摘要或折叠入口。媒体保持自然高度，列表与左侧整体上下对齐，长 P 列表内部滚动，开始/高级按钮独立在底部右侧。普通单视频仍单列。
- P1 详情补充父级缺失的 UP 主/封面，无额外 yt-dlp 调用，沿用超时/大小及不携带 Cookie 的图片预览边界；图片仅显示，不回传到匹配或入队请求。
- 合集中多 P 按父项收起、可展开；父项全选/取消/半选，摘要显示已选数量、大小及错误。子项短标题只用于显示，完整标题仍可访问；原有身份、文件名、策略与任务快照不变，无数据库迁移。

## 验证

- ESLint、TypeScript/Vite 构建通过；保留既有大于 500 kB 的产物提示。
- 前端 55 项通过：包含父组选择、独立 P 键、覆盖继承、保守短标题、类型兼容及预览不进入任务请求。
- Rust Clippy 与全量测试通过：178 项通过、1 项真实站点测试默认忽略。分类测试覆盖同 BV、外层合集、伪造域名、混合 BV 及普通短播放列表。
- `verify-playlist-quality-ui.mjs`：原有 7 场景、合集分 P 的正常/部分入队/读取失败，以及独立 2 P、20 P 明暗场景。检查双栏上下对齐、画质表单直接展示、短标题及封面、子策略、组半选/键盘折叠、滚动/导航保留、精确 P 入队；不访问视频网站、不下载媒体。
- `verify-download-layout-ui.mjs`：单视频、0/1/50 项系列及 1600 至 560px 开发预览回归通过；高级设置和导航状态回归脚本通过。

## 边界

最低原生窗口仍为 1280×800；浏览器小于 1200px 可降级为单列。最多展示/选择 50 个下载叶子条目的边界不变。此记录不代表 Windows/Linux 原生或 macOS WebView 真实下载/合并验收；没有读取用户 Cookie、修改用户数据库或下载媒体。
