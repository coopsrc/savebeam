# 视频/音频分组策略与 FPS

日期：2026-10-23（Asia/Shanghai）。本次方案替代原系列 UI 的视频上限表单，旧记录见 `playlist-quality.md`。

后续调整：四个格式/编码字段改为“自动推荐（优先 MP4/HEVC/M4A/AAC）”；分辨率/FPS/码率仍可用 Best。推荐仅为软偏好，视频按分辨率与名义 FPS 优先后才比格式/编码；音频优先 M4A/AAC，再比兼容性及上游排序。无推荐源自动使用其他候选；手动指定仍严格过滤。`automaticRecommendations` 随快照保存，旧 JSON 缺失默认为 false 保留原排序。新增两项 Rust 测试验证推荐不降分辨率/FPS、缺推荐不跳过、硬选择优先、一体流质量和新旧快照语义。

推荐调整验证：`pnpm check` 全部通过（32 个前端、148 个 Rust 测试）；五组系列界面回归通过，验证四个推荐标签和独立恢复默认，且新推荐标志进入入队快照。此前分组策略阶段的 146 个 Rust 测试结果保留如下。

## 交互与语义

- 统一策略和单项弹窗共用视频/音频分组。视频：分辨率、FPS、源格式、编码；音频：源格式、编码、码率。各项默认 Best，分组恢复不影响另一组；单项应用/取消/继承继续保留。
- 分辨率指定源高度，不是上限；FPS 差值不超过 0.1，30/60 包含 29.97/59.94。音频码率仍在明确标出的 `≤ N kbps` 范围内选最佳；缺少所需参数不冒充匹配。
- 源格式和编码不是转码或最终容器指令；实际流匹配后按兼容性选择 MP4/WebM/MKV。MP3 模式只使用源音频条件。
- 条目显示实际 FPS、格式、编码、码率和所选流大小之和。默认不匹配就跳过；只有明确允许回退 Best 才忽略所有条件，行内标明未满足指定条件。
- 新字段扩展 v12 JSON；旧字段兼容保留，不修改已存在任务。任务固定格式 ID 和完整策略，恢复/重试不读取新策略；无新增网络请求、数据库迁移或依赖。
