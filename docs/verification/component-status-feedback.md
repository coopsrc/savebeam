# 组件检测与在线检查提示分离

2026-10-23。

## 原因与修复

截图中的橙色提示来自进入设置时自动执行的 `get_component_releases`，并不是 `get_component_status` 的版本检测失败。本地四项可用与在线清单网络失败可以同时存在，原来的展示没有明确区分。

- 打开设置及侧栏/Tab 往返不自动联网读取组件目录；保留“检查组件更新”主动操作。
- 本地探测、操作失败、在线目录分别维护错误；四种必需组件均可用才显示全部可用，缺少/过旧/异常不误报。本次探测失败保留旧卡片并注明状态未确认。
- 手动在线检查失败为独立、可关闭提示，说明不影响可用本机组件；本机重测不清除或伪造在线检查结果。
- 在线重试清空旧发行包，失败不暴露过期安装入口；空目录说明无适用发行包，不意味着系统组件已经最新。
- 截图的 Deno 卡片名称缺失和许可证误用由 `java_script_runtime` / `javascript_runtime` 不一致造成。前端将旧字段映射到规范键，Rust 新增输入别名，保留历史序列化及签名载荷，支持正确的名称/许可证/自定义路径/发行卡片。

## 验证

- 前端单元测试：52 项通过，涵盖旧名称归一化、输入不变性、四项完整性、缺少/过旧/异常、重复状态不误报全部可用。
- Rust：名称输入兼容及运行时清单签名往返/篡改拒绝；全量 177 项通过，另 1 项真实站点测试按默认忽略，Clippy 通过。
- `verify-component-status-ui.mjs`：离线四项可用不请求在线目录；手动联网失败/关闭/恢复；本机失败不复用成功摘要；缺少运行时；清空旧目录；空目录；路径参数及旧 runtime wire 键；侧栏返回不重读。
- `verify-settings-tabs-ui.mjs`、`verify-install-guides-ui.mjs`：设置状态保留、三平台明暗分组，以及安装指引平台联动回归。
- ESLint、格式和 TypeScript/Vite 构建验证。保留既有大于 500 kB 的 Vite 单包提示。

所有在线结果、组件路径和剪贴板为隔离 fixture；没有访问真实发行目录、执行安装、改变用户配置或发布清单。原生 UI 仍需用户确认。
