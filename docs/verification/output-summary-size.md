## 大小计算

- 站点返回的精确大小优先于近似大小。
- 缺少近似大小时，Rust 根据总码率和时长计算 `kbps × 1000 × 秒 / 8`。若只有分轨码率，纯视频使用 vbr、纯音频使用 abr，音视频一体格式必须同时有 vbr 和 abr 才能合计；不使用缺少音频的局部码率冒充完整文件大小。
- 前端对所选流大小求和；内置音轨和视频来自同一格式时只计算一次。
- 任一所需流仍缺少大小时显示“暂无法估算”。MP3 转换不使用源文件大小冒充输出体积，显示“转换后待定”；播放列表显示“待逐项解析”。
- 大小为估算值，不含字幕、封面和 JSON，容器封装可能造成少量差异。

## 验证结果

`pnpm check` 通过：14 项前端测试、80 项 Rust 测试，以及 lint、类型检查和前端构建。

Chrome + React StrictMode、模拟 Tauri IPC 的六个界面场景全部通过，确认面板紧邻开始按钮上方。在 1120×900 视口中，各场景面板高度均为 132px，无页面异常：

| 场景                        | 大小显示                       |
| --------------------------- | ------------------------------ |
| 视频 100 MB + 推荐音频 5 MB | 约 105.0 MB                    |
| 改选 6 MB 的音轨            | 约 106.0 MB                    |
| 50 MB 音视频一体格式        | 约 50.0 MB，不重复计算内置音轨 |
| MP3 转换                    | 转换后待定                     |
| 播放列表                    | 待逐项解析                     |
| 缺少大小且无法估算          | 暂无法估算                     |

Rust 测试还覆盖码率估算、逐格式时长优先、站点近似值优先、不完整码率及超大数值拒绝。大小显示沿用任务和历史页面的单位格式；格式化函数已提取为共享工具。
