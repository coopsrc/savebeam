# 删除历史与可选删除下载文件

日期：2026-10-22。

## 交互与范围

点击“删除记录”先打开确认框，列出该历史关联的全部最终媒体路径。“同时删除下载文件”默认不勾选，每次重新打开都恢复为关闭；勾选后确认按钮变为“移入废纸篓并删除记录”。取消、按 Escape 或未确认时均不调用删除接口。提交期间禁用复选框、取消、关闭与重复提交，失败保留确认框及当前选择，提示记录保留与部分文件可能已经移入，可恢复或重试。

目前历史仅完整登记最终媒体文件，所以仅处理确认框列出的文件。不扫描目录，不按标题/前缀推断，不删除字幕、封面、JSON、保留的中间文件或系列目录。页面提示和确认框明确说明这个范围。取消后所有文件保持不变；未勾选时只删数据库历史，不删任务记录或任何文件。

## 后端约束

- `delete_download_history` 接受任务 ID 和可选布尔 `deleteFiles`；缺省/false 延续旧客户端的“仅删记录”。调用在后台线程执行，不阻塞原生 UI 线程。
- 文件路径只从本地历史读取，使用精确 task_id 查询，不接受前端文件列表。先预检所有输出，再逐个操作；只接受已完成任务、原下载目录内的规范绝对路径和普通文件。
- 拒绝目录、相对路径、父级跳转、文件符号链接、祖先链接改变后的路径和越界路径。操作前重新校验，重复路径去重；缺失文件跳过，无记录返回 false。
- 使用 `trash` 5.2.9（MIT）对接系统废纸篓/回收站，应用没有 remove_file 永久删除回退。macOS 显式使用 NSFileManager，避免 Finder 自动化权限；Finder 部分系统不显示“放回原处”时仍可手动拖出恢复。Windows 使用多线程 COM 模式以配合后台线程；具体系统回收站策略与外置盘行为仍需实机验收。
- 只有全部文件处理成功后才删历史行；任一错误保留记录。之前已经成功移入的文件不会自动移回，重试时按缺失文件跳过。文件系统与数据库之间不宣称原子事务，也不清空系统废纸篓。
- 不追踪历史保存后被用户主动替换的普通文件内容；操作针对确认框中列出的当前路径。路径检查不是对外部并发文件系统修改的完整原子隔离保证。

## 验证

Chrome + Vite + 模拟 Tauri IPC 八场景通过：仅删记录、勾选删除、取消、失败后重试、重新打开恢复默认值、提交中禁用并防重复确认、记录已经不存在、原有打开文件/目录及索引传递。确认接口仅传 taskId/deleteFiles，无任意文件路径，所有场景无 pageerror。

Rust 安全测试使用专用临时目录与注入的假废纸篓（目录内 rename），不操作用户真实文件或系统废纸篓。覆盖默认保留文件、精确输出与去重、附属文件和目录保留、失败不永久删除、部分成功重试、全部预检、符号链接与越界拒绝、活动任务拒绝、缺失幂等，以及预检后路径变更的再次检查。

`pnpm check` 全量通过：格式、ESLint、Clippy、TypeScript/Vite 构建、14 项前端测试、98 项 Rust 测试。Vite 仍有既有主包超过 500 kB 提示。原生系统废纸篓真实调用和跨平台实机恢复尚需验收，模拟测试不替代该验收。

参考：[trash API](https://docs.rs/trash/5.2.9/trash/)、[macOS 删除方式](https://docs.rs/trash/5.2.9/trash/macos/enum.DeleteMethod.html)。
